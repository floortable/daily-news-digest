# Daily News Digest 月次保守レビュー

毎月1回、このリポジトリの日次生成・音声生成・公開処理を、品質、信頼性、使用量の3点から保守する。ニュース記事や音声は生成しない。過去チャットを前提にせず、リポジトリ、直近のCodex日次実行1件、直近のGitHub Actions実行を正本とする。

## 調査範囲

1. CIとPagesの直近成功実行について、失敗、警告、注釈、非推奨化を確認する。Action、Node.js、Ubuntuランナー、npm、Astroの公式情報と照合し、`要対応`、`期限まで監視`、`情報のみ`に分類する。
2. 直近の日次実行1件について、モデル呼び出し回数、入力、キャッシュ済み入力、出力、推論、再試行、サブエージェント使用量、主要なツール出力を確認する。キャッシュ率だけで効率を判断せず、完了品質と総使用量で比較する。
3. OpenAI/Codexの公式ドキュメントと、実際に利用している外部ツールの公式ドキュメントだけを一巡し、モデル選定、コンテキスト管理、ツール呼び出し、定期実行に現在の推奨から外れた点がないか確認する。同じ論点の検索を言い換えて繰り返さない。
4. 最新のMuseレビューと直近日次版から、品質上の再発がないか確認する。ただし月次保守で記事本文を再監査せず、プロセス、検査、役割分担の改善候補だけを扱う。

## 判断と実施

- 警告は成功と切り離して評価する。廃止日、強制移行、セキュリティ、互換性に関わるものは、公式の移行先が利用可能なら対応する。将来のホストイメージ変更のように利用者側の設定変更が不要なものは、期限と確認方法を保守記録へ残し、予防目的だけで環境を固定しない。
- モデル変更、サブエージェント追加、プロンプト増量は、直近の実測で品質または使用量の改善が見込める場合だけ行う。大きいモデルへの自動昇格や、同じ資料を複数モデルへ渡す構成は採用しない。
- 機械処理へ移せる定型作業、重複入力、過大なログ、再調査ループを優先して削減する。品質検査そのものは削らず、独立監査は最小限の監査バンドルで維持する。
- 安全で互換性が明確な改善は実装し、`npm run check:all`を通して今回の変更だけをcommit・pushし、CIとPagesを確認する。新しい課金、権限、公開範囲、破壊的変更、判断材料が不十分なモデル変更は行わず、提案に留める。
- 変更がなければcommitしない。結果は、確認した実測、対応した内容、監視継続事項を短くまとめる。成功かつ対応不要なら通知を増やさない。
