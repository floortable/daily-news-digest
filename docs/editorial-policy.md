# 編集・権利ポリシー

この文書は運用上の安全策であり、個別案件に対する法律相談ではない。判断が難しい素材は公開せず、必要に応じて専門家へ確認する。

## 掲載するもの

- 検証済みの原文個別ページへのリンク
- 出典名、公開日時、事実として確認できるメタデータ
- 原文の表現を写さずに作成した短い独自要約と中立的コメント
- 前提知識がない読者にも出来事が分かる、結論・主要事実・適用範囲の3段落、合計240文字以上の独自概要
- 背景、仕組み、影響、比較、未確定点、次に確認すべき事項を説明する300文字以上の独自解説
- 結論、確認済み事実、背景、基礎解説、読者への影響、注意点、次の確認事項を分けた構造化詳細欄
- 短い「注目する理由」「現在の反響」「反響の見立て」。反響は重要性と分け、過熱、妥当、注目不足、評価の分裂、判断時期を中立的に示す
- 必要性があり、引用部分と出典が明確で、必要最小限の引用
- ミーム・流行動画について独自に作成した、発祥、元ネタ、使用素材、拡散経路、反響の検証記録

事実やアイデアと、記事本文の創作的な表現は分けて扱う。見出しであっても特徴的・創作的な表現は安易に複製せず、必要なら独自タイトルにする。

## 掲載しないもの

- 記事本文、写真、図表、動画、サムネイルの無断転載
- 記事の代替になるほど長い要約や引用
- 有料記事、ログイン制限、robots指定、技術的アクセス制限の回避
- 取得元の利用規約やAPI条件に反するスクレイピング
- ライセンス、出典、個別URLを確認できないコンテンツ
- 個人情報、秘密情報、違法または権利侵害のおそれが高い素材

RSSには本サイトの独自要約とリンクだけを含め、原文本文は配信しない。

## ミーム・動画・音源の権利確認

流行を解説することと、素材を再利用できることは別である。元動画、画像、音源、歌詞、字幕、サムネイルは原則転載せず、元投稿または権利者の公式ページへリンクする。曲名や作者を特定できても利用許諾が得られたことにはならない。

`mediaTrend` では発祥を「確認済み」「有力候補」「未特定」「起源に異説あり」に分ける。確認済みとするには投稿者、元URL、投稿日時が必要である。元ネタとBGMも「確認済み」「有力候補」「未特定」を区別し、音源認識サービスやコメント欄だけを唯一の根拠にしない。

削除済み投稿、非公開アカウント、ログイン制限、地域制限を回避して取得しない。本人が意図せず撮影された映像、未成年者、事故、病気、私的場面、差別、嫌がらせ、性的搾取、残虐表現、個人特定につながる内容は二次被害を優先して掲載しない。合成・編集・AI生成の疑いがある場合は断定せず、検証できなければ採用しない。

## データ登録時の確認

各日付ファイルの `contentCompliance` で、その版に含まれる全記事について次を宣言する。

- `policyVersion: 2`: 現行の内容充実・ミーム検証ポリシーで確認した。過去アーカイブのv1はそのまま保持する
- `summariesAreOriginal: true`: 独自表現の要約である
- `copiedBody: false`: 原文本文を複製していない
- `copiedImages: false`: 画像を複製していない
- `quotationsReviewed: true`: 引用がある場合に必要性、長さ、出典表示を確認した
- `sourceTermsReviewed: true`: 取得方法と利用規約を確認した
- `explanationsReviewed: true`: 各記事の独自解説が転載の付け足しではなく、編集上の価値を持つことを確認した

概要は、第1段落で結論と出来事の主体、第2段落で根拠となる主要事実、第3段落で適用範囲・限界・未確定点を示す。読者が「結局何が起きたのか」を最初の段落だけでも把握できるようにし、経緯から書き始めて結論を最後まで隠さない。

解説は概要の言い換えではなく、台本作成と同じく「導入」「事実関係」「基礎解説」「客観評価」「先回り質問」の考え方を使う。専門用語は定義だけで終わらせず、具体像、比較、重要性、未確定点、判断軸まで説明する。情報源の主張、確認済みの事実、編集上の推論を区別し、固有名詞の列挙だけで説明したことにしない。

文字数を満たすための一般論や定型句を加えてはいけない。「原文を継続確認する」「単一の数値だけで判断しない」といった注意は、その記事で次に見る具体的な指標、日付、文書、当事者を示せる場合だけ書く。同じ結論を概要、解説、注目理由、反響評価で言い換えて繰り返さない。

過去に掲載した記事は、訂正、新発表、数値変化、決定、復旧、追加資料など、読者の理解や判断を変える新事実がある場合だけ再掲する。更新がない記事を「再確認」や「継続して重要」という理由で翌日版へ複製しない。同じURLを再掲する場合は `followUp.previousArticleId`、`followUp.checkedAt`、具体的な `followUp.newFacts` を必須とし、新事実をタイトルと概要の先頭で示す。

`attentionAnalysis` では、記事の重要性と人気を分けて記録する。`whyNotable` は注目する理由、`currentReaction` は確認できた反響の範囲、`assessment` と `assessmentComment` は反響が内容に比べて過熱・妥当・不足しているかなどの編集判断を簡潔に示す。数値を確認できない場合は作らず、「特定コミュニティ中心」「反応はまだ限定的」など範囲を明記する。

各記事の `editorialReview` では、独自見出しであることを宣言する。直接引用を使う場合は300文字以内とし、引用文、原文URL、帰属表示、30文字以上の引用目的を必須とする。画像等を使う場合は、許可するライセンス種別、素材URL、ライセンスURL、帰属表示を必須とする。条件を確認できない画像は登録しない。

この宣言がない記事はデータ検証で拒否する。ただし自動検査だけで適法性を保証することはできず、編集者による確認が必要である。

## 申立てと訂正

権利者から削除・訂正依頼が届いた場合は対象記事を非公開にし、原文URL、掲載内容、申立て内容を確認する。公開Issueに個人情報や非公開情報を書かせず、GitHubのPrivate vulnerability reportingなど非公開経路を案内する。明白な誤りや権利侵害は次回定期更新を待たず修正する。
