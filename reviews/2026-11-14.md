## 強化案

- 強化案1：差し戻し指示の事実検証。指示文に含める CVE／VU の有無・期限等の事実主張を、発行前に CERT/CC VINCE API や KEV JSON 等の一次情報と機械照合する。今回は Muse が手作業で訂正したが、指示の誤りはそのまま記事の誤りになるため、発行前の自動検証を入れる。
- 強化案2：publishedAt の一次資料照合。記事の publishedAt を一次資料の published_time／meta（article:published_time、byline 時刻）と機械照合する検査を追加する。Gödel・Palmfrets のずれは、台帳のフィード時刻をそのまま使ったことが原因である。
- 強化案3：generatedAt の自動化（11-13版の強化案6の継続）。assemble 時に edition-meta.json の generatedAt を現在時刻で上書きし、手動設定による未来時刻の混入を防ぐ。monitoringReview の checkedAt も、再確認時の実測時刻を自動記録する。
- 強化案4：同一媒体の機械検査（11-13版の強化案5の継続）。同一 sourceName 4件超を assemble／validate:data で検出し、初稿段階で違反を検出する。今回は JVN 5件が Stage C まで検出されなかった。
- 強化案5：生成セッションの途中終了防止（11-13版の強化案1の継続）。再試行・復旧1・復旧2が途中終了し、生成経路が約810万トークンに達した。工程の完了条件（記事数、assemble 成功、監査バンドル生成）を最終応答の前にスクリプトで機械確認させる等の自動対策を入れる。
- 強化案6：監視ソースの取得制限の区別。monitoringReview の再確認で取得制限・404 が出たソースは、status を「checked」のままにせず「restricted」等で区別し、取得制限のまま「確認済み」としない。取得制限のソースは別経路（一次 JSON の直接取得等）での確認を促す。
- 強化案7：記事単位セッションの narration 扱いの明記。新規記事の指示に narration の要否を明記し、版内での有無の不統一（GhostFrame のみ null）を防ぐ。
- 強化案8：トークン計測の是正。生成・初回の計測値が要約の 748,304 とロールアウトログの 1,075,035 で食い違った。計測は thread_token_usage の最終値を正とし、レビュー執筆時にロールアウトログから再計測する手順を明記する。
